# 上下文压缩与长期记忆：调研交接

2026-11-07，从 Windows 交给 Mac 接着做。

## 背景和要求

- 主人反馈：现在的压缩让最近的聊天丢了很多信息。
- 想要一份全局共享的「对主人的记忆」，电脑和手机共用，感觉要像 Claude App 那样。
- 要对比 opencode 等开源智能体和各类框架，看看除了「满了再压」还有没有更好的办法。
- 要弄清上下文该定多大、取决于什么。

## 一、我们现在的压缩

文件：`clients/desktop/src/lib/llm/context-window.ts`，手机端 `clients/mobile/src/lib/llm/context-window.ts` 是同一份逻辑。

- **门槛：** 按字数估算，超过 48,000 字就压，压到 24,000 字。
- **保留：** 最近 2 轮原样保留；更早轮次里超过 600 字的工具结果，只留开头 300 字。
- **摘要：** 被裁掉的轮次不调模型，每轮机械摘一行「主人：… → 回应：…」，各截 60 字，最多 24 行。

**丢信息的原因：**

1. **门槛太低。** 用到的模型窗口在 25.6 万到 100 万 token 之间。qwen3.6-flash 在 25.6 万以内同价，缓存命中也便宜。
2. **工具结果没有单独上限。** 一次大结果就能把总量顶过门槛，最后只剩最近 2 轮是完整的。
3. **摘要是机械截断。** 中间讨论出的结论、细节和数字都丢了。
4. **切会话或重启会丢工具记录。** `App.tsx` 的 `sessionMessagesToLLMHistory` 跳过了 `role === 'tool'`，工具调用和结果全丢。
5. **旧摘要会被挤掉。** 旧摘要整段当成一行并进新摘要，里面还嵌套了 `<system-reminder>`。超过 24 行后最早的部分会被挤掉。

## 二、Claude Code 怎么压缩

源码只在 Windows 机上（Mac 没有这份，上面的结论已经够用）：`D:\my_pro\ClaudeCodeOpenSource\claude-code-sourcemap-main\restored-src\src`，主要在 `services/compact/`、`query.ts`、`utils/context.ts`。

### 什么时候触发

- **有效窗口：** 模型窗口 − min(最大输出, 2 万)。
- **自动压缩阈值：** 有效窗口 − 1.3 万。
- **例子：** 20 万窗口、3.2 万输出时，有效窗口是 18 万：
  - 14.7 万开始提示；
  - 16.7 万自动压缩；
  - 17.7 万直接拦住不发请求。
- **怎么算 token：** 上一次回复的真实用量（输入 + 缓存写 + 缓存读 + 输出），加上之后新消息的粗估。粗估按字符数 / 4，每张图算 2000。
- **什么时候检查：** 每次请求前都检查。顺序是：工具结果总量预算 → 微压缩 → 自动压缩。

### 写摘要之前先做的

- **工具结果总量预算：** 一条消息里工具结果加起来超过 20 万字符时，最大的几条存到磁盘，原处只留约 2KB 预览。一条结果处理一次后就不再改，保证缓存前缀不变。
- **按时间清理（默认关）：** 离上次回复超过 60 分钟（缓存已过期）时，除最近 5 个以外的工具结果都换成「旧工具结果已清除」。
- **接口侧：** Anthropic 接口支持清理旧工具调用和思考内容（`clear_tool_uses` / `clear_thinking`），Claude Code 里是内部开关。

### 完整压缩

- **怎么请求：** 用同一个模型、同样的前缀分出一次请求，所以能吃缓存。这次请求禁止调用工具。
- **摘要格式：** 先写 `<analysis>` 草稿，再写 9 段摘要：
  1. 主要请求与意图
  2. 关键概念
  3. 文件与代码
  4. 错误与修复
  5. 问题解决
  6. 所有用户消息
  7. 待办
  8. 当前工作
  9. 下一步（附原话）
- **压缩后带回：**
  - 摘要；
  - 重新读最近 5 个文件，每个不超过 5000 token，合计不超过 5 万；
  - 计划和技能重新附上；
  - 一句「接着做，不要再问」。

### 另一条路：会话笔记压缩

- **平时：** 后台分出一个代理边聊边维护一份 markdown 笔记。对话到 1 万 token 后开始写，之后每增长 5000 token 更新一次。
- **压缩时不调模型：** 用笔记，加上原样保留的最近消息。保留量至少 1 万 token 且至少 5 条消息，上限 4 万；不拆散工具调用和它的结果。

### 失败处理

- 连续失败 3 次就停止自动压缩。
- 压缩请求本身太长时，从最旧的部分往前丢再重试，最多 3 次。

## 三、Claude Code 的长期记忆

源码在 `memdir/`、`services/extractMemories/`、`services/autoDream/`。

- **怎么存：**
  - 每个项目一个目录，一条记忆一个 `.md` 文件。
  - 文件头写 name、description、type，type 分四类：user、feedback、project、reference。
  - `MEMORY.md` 只做索引，每条一行，最多 200 行、25KB。
- **怎么写：**
  - 主模型按系统提示词自己写：先看有没有能更新的旧记忆，不重复；发现错了就改或删；相对日期改成绝对日期。
  - 后台还有一个代理，每轮结束后从最近的消息里提取记忆。这一轮主模型自己写过就跳过，而且它只能写记忆目录。
- **怎么整理：** 距上次整理超过 24 小时、并且中间有 5 个以上会话时，后台代理会合并重复、删掉互相矛盾的、修剪索引。
- **怎么读：**
  - 默认每次会话把索引放进上下文，具体文件需要时再读。
  - 另一种模式是每轮用小模型从记忆清单里挑最多 5 条附上，每条不超过 4KB。
- **新鲜度：**
  - 每条记忆标上「N 天前」写的。
  - 提醒模型：记忆是写下时的事实，和现在冲突时以现在为准，并顺手更新。
- **和缓存的关系：** 记忆段算一次就固定。「N 天前」提前算好，免得每轮都变、打掉缓存。

## 五、初步方向（调研补全后再定）

**压缩：**
- 改成按 token 计数，用接口返回的真实用量。
- 门槛按模型窗口和价格阶梯来定。
- 先限制单个工具结果的体量、清理旧工具结果，最后才让模型写结构化摘要。
- 或者学会话笔记压缩：平时增量维护笔记，压缩时不用等。

**恢复会话：** 切会话或重启时，保留工具调用和结果。

**记忆：**
- 全局一份「关于主人」的记忆，电脑和手机同步，做成 Claude App 那种感觉：
  - 定期总结；
  - 主人可以看、可以改；
  - 需要时能搜过去的聊天。
- 放在稳定的前缀里，不打掉缓存。
