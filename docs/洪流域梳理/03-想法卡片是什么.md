# 03 · 想法卡片是什么

## 这个结是什么

协议志要求：愿景日记以想法卡片为单位，卡片的 id 和原话不能丢。可想法卡片自己要重新定义。这篇把它定下来。

## 现在有什么

- 一张想法卡是库里独立的一行：一段话、创建时间，可选地指向一个视频。
- 两个来路：在「想法卡片」页的输入框里写；和 Fairy 聊天时沉淀出来。
- 先有卡，再回头挂到视频的某一句上。挂漏了就成了「损坏」的卡。

## 你说过的

- 「想法卡片是什么，其实也是后面要定义的东西，首先它是一个特殊页面的特殊组件，其次，想法卡片会收集所有分类页面里面对应段落的“个人批注笔记”」
- 「批注的紫色字是想法卡片」
- 「我非常看中“我在这个语境里面留下什么痕迹”这件事」

## 问题

**问题一：一条批注，就是一张想法卡片吗？**

你在原文里插的每一段紫字，各有自己的 id、原话、时间。

我的倾向：是。批注是它在语境里的样子，想法卡片是它被收拢后的样子，是同一个东西。协议志要的「卡片 id 和原话」就是这条批注的 id 和那段紫字。

你的回答：是，一条批注就是一个想法卡，不过我们这里定义的一条批注，不仅仅是一段话，如果我们高亮了多个句子去在一块批注，那也是一条批注

**问题二：没有语境的想法，写在哪？**

比如走路时冒出来的一句，或者一篇愿景日记。它没有贴着哪本书、哪个视频。

- 每天一页「随手记」：没有语境的想法都落在当天那一页，这一页就是它的语境。
- 不要语境：允许一张卡孤零零地存在，和现在一样。
- 没有真正无语境的想法：总能说出它是看了什么、聊了什么想到的，写的时候顺手指一下。

我的倾向：第一种。和 Fairy 聊出来的，语境就是那段聊天；其余的落进当天那一页。这样每条批注都有一个能点回去的地方，不会再有「损坏」的卡。

你的回答：没问题，就叫未关联语境的想法卡片，别整随手记的新名词

**问题三：那个「特殊页面的特殊组件」，打开看到什么？**

我猜的：一条时间流，最新的在上面。每条是你的一段批注，带着它贴着的那几句原文、来自哪一页、挂了哪些锚点。点一下回到原处。

- 能不能在这里直接写新的？（写了就落进当天的随手记。）
- 除了按时间，还要按什么看：按语境的分类、按锚点、按三类？

我的倾向：能直接写。先只做按时间和按锚点两种，别的等用起来再加。

你的回答：类似flomo一样，有个热力图，右侧是所有想法卡片的集合，按照时间倒序。其实在这里写新的就是无语境的随手记，也可以随时关联语境。这也是所有我们自己输出存在的地方，包括我们写系统性文章（也会以想法卡片的形式存储进来）

**问题四：已有的那些想法卡，以后变成什么？**

这一条只问方向，真要动数据时我会再单独问你一次。

- 指向了视频的：变成那个视频页上的一条批注。
- 没指向任何东西的：按它的创建日期，落进那一天的随手记。
- id、原话、创建时间都原样带过去。

我的倾向：就这样。

你的回答：依旧是想法卡片啊，你在说什么，数据库方面迁移到notion数据格式合理的方案

**顺带（协议志 04 篇末的口子）：锚点句系统做出来之前，愿景锚点句先住在哪？**

- 先住在协议志这边：每条愿景存三样，当前这一句、以前的各版、来源。这边做好再原样搬过来。
- 先做笔记基底和锚点句系统，协议志等它。

我的倾向：第一条。

你的回答：笔记基底先做出来

## 结论（2026-11-23，按你的回答整理）

- **一条批注就是一张想法卡片。** 一条批注不限于一段话：高亮了好几个句子、放在一块批的，也算一条。
- **没贴着任何语境的，就叫「未关联语境的想法卡片」。** 不另起「随手记」这种新名词。它以后可以随时关联到语境上。
- **想法卡片那一页像 flomo**：有热力图，右侧是所有想法卡片的集合，按时间倒序。可以在这里直接写新的，写出来就是未关联语境的想法卡片。
- **这里是你自己所有输出存在的地方。** 写系统性的文章，也以想法卡片的形式存进来。
- **已有的想法卡依旧是想法卡片。** 数据库迁到合理的 Notion 式数据格式。
- **笔记基底先做出来。**（协议志第 04 篇末那个口子的回答：协议志等它。）

以下是我的理解，错了划掉：

- 问题四我问歪了。旧卡不用「变成」别的东西，它们本来就是想法卡片，只是存法要跟着新基底换。
- 「每天一页」我撤回。未关联语境的想法卡片就是没有语境，不硬塞一个日期页给它。
- 一篇系统性的文章也是一张想法卡片，所以一张卡可以很长，里面可以有很多块。愿景日记就是这一类。
- 迁数据时，卡的 id、原话、创建时间原样带过去。真要动数据之前我再单独问你。
