## 现在洪流域有什么

以代码为准（2026-11-20 查）。真实数据库我没有打开看，有多少张卡、多少条锚点不知道。

电脑端「洪流域」有四个视图，外加一个旧的示范页：

| 视图 | 里面是什么 | 存在哪 |
|---|---|---|
| 想法卡片 | 一张卡一段话。输入框里写，或者和 Fairy 聊天时沉淀出来。可以带一个「语境」标签，指向某个视频 | 表 `context_cards` |
| 语境库 | 只有一种东西：转录过的 B 站视频。它不是存下来的卡，是每次打开时从视频表现拼的 | 视频表 `bili_video_assets` |
| 锚点域 | 认知地图：一条锚点句一个球，按意思相近聚成山，山名 AI 起 | `anchors`、`anchor_embeddings`、`anchor_cluster_names` |
| 笔记 | Notion 式的页面树，块编辑、分栏、附件、回收站、搜索 | 表 `note_pages` |
| 洪流域（静态示范） | 最早的假数据样板，不接数据库 | 无 |

几条容易忽略的事实：

- **笔记和另外三样完全不连。** 两套表，互相没有任何引用。Fairy 能读写想法卡和锚点，读不到笔记。
- **锚点句现在的样子**：一行 = 一句话 + 三类之一（动机 / 观点 / 实践）。同一句同一类全库只有一条，可以挂在多张卡上。挂的方式是「绑定」：卡里的一段文字 + 你当时的原话 + 这段话提出的几条锚点句。
- **对照协议志要的三样**：
  - 当前这一句：有。
  - 来源多张卡：有，就是上面的绑定。
  - 以前的各版：没有。改句子是直接盖掉，旧的不留。
  - 浓缩成关键词：没有。（库里那一列叫 `keyword`，存的其实是整句。）
- **锚点不只锚点域在用。** 协议志的动机云按锚点 id 存每颗动机的去向和蓝图（表 `motive_protocols`）；Fairy 有七个工具读写想法卡和锚点；手机端的 Fairy 直接连电脑读写这些表。清锚点域时这几处都会被牵到。
- **都不同步。** 想法卡、锚点、笔记只在电脑上。手机上没有笔记。
- **手机端的「洪流域」是另一样东西**：无障碍服务还原出来的看过什么的时间线，和上面这些没有打通。

## 协议志那边对这里的要求

- 愿景日记以想法卡片为单位。一条愿景是一句愿景锚点句，协议领养的是这一句。
- 锚点句系统至少要有三样：当前这一句、以前的各版（可以迭代）、来源（多张想法卡片，或多个语境）。
- 不管想法卡片以后改成什么形态，卡片的 id 和卡片上的原话不能丢。

- 关于想法卡片和锚点地图：「现在的形态我不太认可」。
